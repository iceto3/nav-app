# Architecture

`index.html` loads three scripts in order:

1. `vendor/maplibre-gl.js` (MapLibre GL 4.7.1, as a classic script)
2. `vendor/pmtiles.js`
3. `app.js` (a module)

`app.js` is only an entry point. It imports `src/main.js` and carries the `APP_VERSION='vNN'` marker that the auto-update check of already-open clients reads. The `<link rel="modulepreload">` block is generated by `scripts/gen-preload.mjs`, so every module is fetched in parallel instead of one import depth per round trip.

```
app.js                 entry + version marker
src/
  config.js            ALL tunables: version, URLs, attribution, data files, start view, fonts, zooms, timings
  main.js              bootstrap: imports feature modules (registration), creates the map, wires UI in order
  api.js               window.NavApp – the only public surface (editor, tests)
  core/                no map/DOM knowledge of features
    registry.js        registerFeature(), LAYER_SLOTS (z-order), collectLayers(), applyThemes(), runOnLoad()
    events.js          app event bus: emit()/on()
    state.js           shared runtime state (oldChart, editing, me, heading, follow, navigating)
    dom.js geo.js errorReporter.js
  map/
    sources.js         ordered source catalog (order = attribution order)
    bases.js           BASES (radio) and OVERLAYS (checkboxes) for the layer switcher
    createMap.js       MapLibre map, pmtiles protocol, glyph routing, controls
    theme.js           setOldTheme(), switchBase(), applyInitialBase()
  layers/              one feature module per layer group; each calls registerFeature()
    basemaps oldChart userEdits depth openSeaMap route seamarks labels
  icons/               icon table (id -> SVG) and its registration with the map
    svg.js             shared SVG parts (colours, bands, shapes, topmarks)
    seamarkSat.js      set D – illustrated (ids 'D_<key>')
    seamarkOld.js      set E – engraved Old chart (ids '<key>')
    poiIcons.js lightVariants.js index.js (ICONS)  loader.js (canvas rasterising, PNG POIs, dots, fallback)
  seamarks/            data side of seamarks/POIs
    classify.js        OSM tags -> [icon, kind, priority], light labels (pure)
    store.js           bundled + live data, harbour dedupe, user-edit hide/pin, 'marks' source updates
    overpass.js popup.js
  location/            boat.js (GPS, compass, marker, follow), rings.js (range rings feature)
  route/               router.js (destination, OSRM, panel), navigation.js (guidance, voice), instructions.js, format.js
  ui/                  DOM controls: zoomSlider scaleBar layerSwitcher search statusPill versionBadge toast oldDecor depthNote
  app/maintenance.js   service-worker/cache cleanup, auto-update
editor/                developer editor (separate page, ES module, uses only window.NavApp)
tests/                 Playwright suite + static server with Range support
scripts/               deploy.sh, bump-version.sh, gen-preload.mjs, measure-load.mjs
```

## Principles
- **Core does not know features.** A layer group is a module that calls `registerFeature({id, layers:[{slot, spec}], applyTheme, onLoad})`. The style is built from the registry (`collectLayers()` walks `LAYER_SLOTS` bottom to top). Switching base calls every `applyTheme(map, old)`. Adding a layer never edits core.
- **Sources live in one catalog** (`map/sources.js`), because their order sets the attribution order.
- **No magic numbers in logic.** Tunables live in `config.js`. Styling literals (paint colours, sizes) stay in their layer module, next to the layer they style.
- **Modules communicate through** imports (downward), the event bus (upward or sideways) and `state`. There are no loose globals; the editor and tests use `window.NavApp`.
- **Cache-busting:** every relative import and HTML reference carries the same `?v=NN`. Two different URLs for one module would instantiate it twice, giving two registries. ESLint (`no-restricted-syntax`) and `tests/static.spec.js` enforce this, and `scripts/bump-version.sh` keeps the values equal.
- **Naming:**
  - files are camelCase; exported functions are verbs (`initX`, `loadX`, `applyX`)
  - constants are UPPER_CASE
  - icon ids: `D_` prefix for satellite/modern, bare for Old chart, `pdot_`/`opdot_` for POI dots, `_R/_G/...` suffixes for light colours

## Events (core/events.js)

| event | detail | emitted by |
|---|---|---|
| `themechange` | `{old}` | map/theme.js (on every base switch) |
| `overlaychange` | `{key, on}` | ui/layerSwitcher.js |
| `useredits` | bundled user-edits FeatureCollection | seamarks/store.js |
| `marksready` | – | main.js (icons registered) |
| `position` | `[lat, lon]` | location/boat.js |

## Editor API (`window.NavApp`, frozen)

| Member | What it gives |
|---|---|
| `version`, `map` | app version and the map instance |
| `isOldChart()` | whether the Old chart base is active |
| `setEditing(bool)` | suppresses app popups and dropped pins (replaces the old shim.js / setDest wrapper) |
| `on(type, fn)` | subscribes to app events |
| `seamarks` | `{classify, markById, refresh, getStaticFeatures, getDeletedIds}` |
| `userEdits` | `{caseLayer, shoreLayers, contourLayers, PIER_RADIUS_M, applyTheme(prefix), getData()}` |
| `debug` | `{marksReady(), harbourClusters(), showError, featureIds(), icons()}` |

## Startup order (main.js)

The order matches v33 so that DOM stacking and behaviour stay identical:

1. error reporter
2. map
3. oldDecor, zoom slider, scale bar, layer switcher, location, search, router/navigation, status pill, version badge
4. ring hooks, missing-image fallback, seamark store, popups
5. icons → POI PNGs → dots → rings → re-theme if Old chart → `marksready` → first seamark load
6. API, cache cleanup, initial base, auto-update

## Known quirks kept on purpose (pixel parity with v33)
- The scale bar uses 156543.03392 m/px at z0, while the accuracy circle and range rings use 40075016.686/(512·2^z). Both are kept.
- The modern depth-contour label halo is `rgba(0,40,60,.8)` (user-edit contours use `.85`).
- On a satellite start only the user-edit theme is applied. The other theme hooks run on the first base switch, which gives the same result because the style defaults are the satellite theme.
- Glyph (`?v=16`) and POI PNG (`?v=23`) revisions are independent of the app version (`config.ASSET_REV`).
